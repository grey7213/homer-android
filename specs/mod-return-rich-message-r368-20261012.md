phone-owned archives, owner/epoch isolation, regex, scripts, Mod settings and
memory. No source submission, official publishing or server deployment.

1. Mod → get more → Back retains the same outer chat and runtime document,
   messages, draft and settings; does not navigate the inner runtime to workshop.
2. Strong-rendered iframe messages invoke the existing message menu on a text
   long-press, including rollback. Controls, links, scrolling and editable native
   selection remain usable. Removed/rebound/old-account frames cannot act.
3. Investigate large-card latency using original Wind evidence and current
   timings. Do not call a clean-room adaptation a literal source transplant,
   hide waits or disable original card behavior.
4. ChatArchive requires genuine ordinary-game implementation. Existing recovered
   AOT signatures and Android bridge are not the protected Hot gameplay source.
   No protected payload bypass; missing original source remains a separate gate.

## Risks / verification limits

- Inner iframe navigation is not covered by main-frame retained WebView routing.
- Long-press events do not bubble across iframe documents. Binding only to a
  message number permits stale-frame or cross-account actions; bind the exact
  message object plus launch/epoch and frame document.
- Keep interactive controls and explicit copy/selection workflows usable.
- A synthetic browser fixture is not native OEM/device evidence. APK hashes do
  not prove production providers or cold-start latency.
- Wind has native and Web paths; distinguish the actually wired path from old
  unused components. Direct code inclusion also needs confirmed reuse rights.
- Main ChatArchive 1.2.6 Hot implementation is not currently recovered. Do not
  silently substitute the equivalent-reconstruction module.
