# R26：界面模板、酒馆助手、对话设置与标签反馈

## 用户纠正与范围

- 用户已认可 R25 速度，维持已有预热、持久页面、会话历史和缓存。
- “界面模板和正则是一个东西”：合并入口、列表、导入、编辑和预览；旧资源与旧链接不能丢失。不能把名称不同误当成不同产品。
- 案例1原先只解释；本轮用户明确要求修复。基于酒馆助手官方渲染器行为和实际包内证据处理，不能伪称未安装扩展，也不写单卡特例。
- 原生验收发现导入卡的备用开场存在于角色定义，却在云消息绑定时遗漏；补齐通用的开场候选恢复，保留已编辑开场和旧候选的顺序/索引，不触发生成。
- 已证实后端把 302 万字符的互动模板截为 24 万，需有界无损保存及同版本原快照的安全恢复；提示词模板的代码块二次解析也需真实互动回归，不以 iframe 存在当成功。
- 重做右上角功能界面，不改聊天文本、创作者页面内容、现有业务权限。
- 角色详情标签长按菜单：点赞增加推荐权重，不感兴趣降低权重，屏蔽排除；持久化、撤销、账户隔离，并在现有推荐路径即时生效。
- 仅本地软件验收，不提交、推送或部署生产。

## 验收

- 实际案例卡进入与历史重开均无可见源码块；普通代码块不误隐藏；前端交互可用，不重复渲染；不执行作者安装插件按钮的管理员行为。
- 创作工坊只有一个界面模板（正则）入口，旧两种数据可查、导入、预览、保存和应用；不静默删除/迁移用户资源。
- 对话菜单及模型、预设、长记忆、Mod、外观逐页截图和操作，现有控制事件/权限不重写。
- 长按拖动取消、边缘弹窗限位、键盘可操作；明确当前反馈，可撤销；存储失败不假成功。
- 推荐由原先已鉴权候选集过滤/评分；屏蔽不因关闭个性化或排序切换失效；不影响用户自己的管理、历史与直达详情。
- 标签反馈仅存现有按账户隔离本机偏好，不收集聊天内容，不声称云端同步或训练了机器学习模型。
- 维持 R25 路径速度与历史不重复；补丁/最终 APK 字节核验，不丢前轮成果。

## 风险与检查

- 酒馆助手 iframe 与 Markdown/code CSS 冲突：定位实际样式和调用顺序，不能隐藏所有 pre 来掩盖渲染失败。
- ui_template 旧数据可能是 HTML 而非正则：保持原始记录，转换必须显式、可预览，不把空匹配规则加入每条消息。
- 弹窗节点已有事件监听：使用原节点重新组织，避免重复监听/丢失保存。
- 本地推荐作用于已加载候选，不承诺服务端全库排序；屏蔽跨推荐/搜索列表应统一。
- 不输出凭据、会话 token；使用既有本机测试账户与隔离数据库。
