## 已确认的机制

反编译源码路径均相对于 `output/mobile-r28/wind-jadx/sources/org/nebula/horizon/composeai/`。

| 事实 | 证据位置 | 作用与边界 |
| --- | --- | --- |
| Activity 启动时初始化共享聊天 WebView | `MainActivity.java:368` | 不等用户第一次点进聊天才创建显示容器。 |
| 单例初始化有幂等检查；加载 APK 内的 `webapp/index.html` | `ui/webview/WebViewSingleton.java:173` | 重复调用不再次创建 WebView；本地页面不依赖首次下载。 |
| 页面之间移动同一个 WebView；离开时仅拆离父容器 | `ui/webview/WebViewSingleton.java` 的 `attachToParent`、`detachFromParent` | 与销毁、重新 loadUrl 是不同的生命周期；显式 destroy 才清实例。 |
| 页面全部离开后保留状态；未就绪的指令排队，React 就绪后再发送 | `ui/webview/WebViewManager.java` 的 `detachWebView`、`flushPending`、`sendOrQueue` | 排队数据指令，不要求每次导航重建整个运行时。 |
| 同卡已有配置及会话状态时走热返回，跳过冷加载；恢复中断流 | `ui/features/conversation/ConversationViewModel.java:10497` | 返回原会话无需重新走整条初始化链；流恢复与页面重建分开。 |
| 相同消息指纹不重复重置消息；流式过程中延后会覆盖消息的整包刷新 | 同文件 `loadMessagesIntoWebView`，约 `13037` | 避免已显示对话闪空、重复渲染或覆盖正在生成的内容。 |
| 卡资料、配置有本地 Room 有效缓存和后台刷新 | `core/data/local/room/CacheManager.java` 的 `getAppWithBackgroundRefresh`、`getConfigWithBackgroundRefresh` | 已读到卡资料有效缓存四小时内先返回、另起刷新分支。缓存缺失仍要请求。 |
| 消息不等于无条件本地优先 | 同文件 `getMessagesWithNetworkFirst` 的可读分支 | 消息路径存在先请求、写本地、失败回退。不能把“风月纯本地、完全无网络等待”当事实。 |
| 风月自身也有加载与错误状态 | `WebViewSingleton`、对应 WebViewClient 的 loading/error 回调，以及 `loadMessages` 的可选 overlay | 重点是把重复初始化移出用户切换路径，不是把加载字样删掉。 |

## 与惑梦当前实现的具体差异

惑梦也已经有 APK 本地资源、SQLite 快照、页面常驻和普通聊天预热，因此“惑梦没缓存，风月有缓存”不是准确解释。

1. `HomerActivity.scheduleDialoguePreparation()` 在账号可用、处于五个普通页面时，延迟 600ms 创建 `/app/chat.html?prewarm=1`；这份运行时属于 `persistentPages["chat"]`。
2. 管理后台是另一个常驻页面键 `admin`。`frontend/assets/js/admin-dialogue.js:preparePreviewRuntime()` 又创建自己的 `#admin-dialogue-frame`，从 `/module/dialogue/` 初始化另一套运行时。
3. 后台 `startPreview()` 等待后台这一份运行时的 `core-ready` 再绑定；它没有取得普通聊天已预热的实例。因此普通聊天已经快，不代表第一次打开后台试聊也快。
4. SillyTavern 前端目前同时承载聊天显示、原生设置、扩展发现/激活、角色绑定等。后台第二份运行时会重复这些工作；最近压缩编辑器/选择器/观察器只能缩短它，无法消除“第二次初始化”。
5. 当前测试日志记录的是后台 iframe 的实际初始化和绘制，并不能代表 Android 进程内共享容器复用已经完成。此前将局部提速当成完成，是验收门槛错误。

## 独立行为规格（不是复制风月代码）

### 状态与接口

- 每个已验证账号会话拥有一个可复用的聊天执行宿主；冷启动、就绪、绑定中、已绑定、生成中、失败六种状态明确区分。
- 普通聊天和管理员工作区都向宿主发送有范围的绑定命令，不能各自新建引擎。页面导航不触发宿主销毁。
- 普通范围键至少含账号、角色、会话；管理范围必须额外区分 preview 与普通存档，不能拿普通会话 ID 充当测试会话。
- 绑定后只提交当前 generation 的结果；旧请求、迟到消息和旧令牌不能覆盖新范围。
- 切换账号、权限失效、渲染进程崩溃需要明确失效/重建，不能为速度复用上一账号的缓存或管理员配置。
- 同一范围重复进入复用状态；有效消息指纹相同不清屏、不重绘全文。生成中不以旧整包历史覆盖新片段。
- 本地资料可先读并后台校准；真实角色脚本、世界书、正则、预设和当前模型在生成前必须正确绑定。不能用没有执行能力的快照冒充完整就绪。
- 管理草稿保持仅本次预览；模型请求仍由服务端验证权限与扣费，普通用户不能通过发宿主命令取得管理员功能。

### 验收场景

1. 全新进程立即进后台，记录宿主创建次数、首屏绘制和可发送时间；不先手动等待预热。
2. 普通聊天 → 后台试聊 → 原普通聊天：实例不重复初始化，两个范围数据隔离，原草稿和历史不丢失。
3. 同一会话多次进入不清屏；不同卡连续切换不串消息。
4. 切换账号、普通账号构造管理员命令、权限失效均不能复用越权内容。
5. 请求失败有重试且可恢复；生成中回到页面不覆盖正在接收的内容。
6. 真实扩展与模型/预设/世界书/正则修改、生成和日志复制通过后，再判断性能是否达标。
