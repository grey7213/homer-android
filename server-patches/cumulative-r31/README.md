# 唯一服务端累计补丁：R25–R31

> 已被 `../cumulative-r32/backend.patch` 替代。此目录只用于历史核对，不再单独应用。

本次整合旧 PR #13（R25–R27）与后续 R29 管理会话/正则改动。**只处理本目录的 `backend.patch`，不要先叠加 mobile-r25、mobile-r26 或 r29 的补丁。** 旧目录仅保留历史追溯。

包含六个 tools 模块：模型显示分组、创作资源/界面模板兼容、无损正则、开场白源阶段处理、管理员独立完整会话配置与生成接口、真实 JavaScript 正则执行、生成错误编号。两个 helper 的完整源码也在本目录，且已包含在补丁内，无需再次复制。

## 应用

1. 备份业务后端、Node 会话运行时、资源和数据库。不要覆盖账号、对话和密钥配置。
2. 在业务服务器源码根执行 `git apply --check <本目录/backend.patch>`。原始基线与结果的 LF 归一化 SHA-256 在 `manifest.json`。已应用过旧补丁或生产代码不同的，先审查合并差异，不能强行覆盖或重复应用。
3. 检查通过再 `git apply <本目录/backend.patch>`。确保服务器已有 Node；非默认路径设置 `HOMER_NODE_BINARY`，不在源码中填密钥。
4. 同步本 PR 唯一的 `web-patches/*cumulative-r25-r31.patch`，其中包含 Node 服务端接口，不只是 APK 内的静态文件。重启 Python 业务服务和 Node 对话服务。
5. 测试管理员会话工作区可用、普通用户/匿名被拒绝、会话草稿不写全局配置和普通历史、官方正则实际执行、模型分组/显示名正确。然后按既有流程出正式签名 APK，并升级热更新槽版本，避免旧资源覆盖。

本 PR 没有部署生产、没有数据库迁移；回滚用三个组件同一套备份，不清空用户数据。
