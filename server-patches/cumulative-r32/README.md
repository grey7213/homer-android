# R25–R32 唯一业务后端累计补丁

本目录 `backend.patch` 包含旧 #13、#14 对应业务后端全部改动及 R32 失败生成免扣分。
**不要叠加 cumulative-r31、mobile-r26 或 r29 的补丁。** 原始基线不变，详见 `manifest.json` 的 LF 归一化哈希。

## R32

- HTTP 200 中的 JSON/SSE 错误、明确失败的终止原因、空白回复、损坏响应、未正常结束的流不会进入结算；不能把 message 错误字段或 `[DONE]` 当成生成内容。
- 成功生成并确认非空后，积分扣除、账目写入与最终响应写出在同一结算范围；最终写出抛错则回滚余额和事件，保持免费/奖励/付费积分来源一致。并发请求通过原 Store 锁和 SQLite 事务防止超支。
- 没有开放“客户端自行申诉退款”的接口；不追溯调整过去的账目。服务器写出成功不能证明手机已收到；纯客户端丢包无法据此无条件退款。
- 保留现有成功计价、权限校验、管理员预览隔离和错误编号。结算时余额已被其他请求消耗，仍返回余额不足而非模型紧张。

## 维护者

1. 备份业务服务、Node 对话服务、资源和数据库。
2. 业务源码根先 `git apply --check <backend.patch>`，通过后再应用；已有部分旧改动的生产基线必须人工审查合并，不能覆盖。
3. 同时应用本 PR 的唯一 `web-patches/*cumulative-r25-r32.patch`，其中包含 Node 接口与客户端模型发送锁；Python helper 与 JS regex worker 已包含在服务端补丁，不遗漏。
4. 重启两个服务，测试上游失败余额/账目不变、错误提示、发送锁与换模型恢复；再按现有渠道出正式签名 APK、同步匹配版本的热更新资源。只更新 APK 不会修好服务器扣费。

没有数据库迁移。本机测试与官网发布分开，本次不自动部署生产。
