# R20 创作积分收益：服务端更新

这是待部署的源码补丁，不是生产已上线声明。Android 安装包只能更新界面，不能替代服务器结算更新。

## 规则

- 只发放积分，写入现有奖励积分余额，不存在现金金额、兑换或提现。
- 默认收益率 35%，以角色卡实际成功扣除的积分为基数；免费、奖励、充值积分沿用原扣除顺序。
- 每次消费产生的小数按卡和作者累计，满 1 积分入账。后台比例可设 0%–100%，最多两位小数；调整仅影响之后消费。
- 作者归属取服务器角色卡记录，不接受客户端传入的收益人。用户只获得自己的每张卡累计积分，不返回玩家身份或消费明细。
- 当前“每个玩家”包含作者本人使用自己的卡；不自动排除。只对上线后的成功消费结算，不追溯历史扣费。
- 邀请奖励接口值为 null，界面明确显示尚未接入；本次没有新增邀请规则。
- 扣费、收益、余数与回执在同一 SQLite 事务中。已有回复 ID/新补充的 completion ID 用于重复结算去重；新的生成仍是独立消费。
- 本补丁未创建退款业务；将来接入退款必须同步定义分成冲正，不能仅返还玩家积分。

## 应用

基线：2026-09-18 获取的 AIXingYue 源码快照 `tools/ai_fengyue_local_server.py`。不是整个后端替换包；版本不同不得强行覆盖。

1. 先在实际后端工作副本检查 `integration.patch`，确认消费仍经过 `Store.spend_credit_points`。使用数据库一致性备份，保留原代码。
2. 在该后端根目录执行：

   ```sh
   git apply --check /path/to/integration.patch
   git apply /path/to/integration.patch
   python -m py_compile tools/ai_fengyue_local_server.py tools/creator_earnings.py
   ```

   补丁已经包含新模块，不要再重复追加模块代码。若 check 失败，按差异合并，不覆盖完整服务端文件。
3. 在测试环境按原服务启动方式重启。原 `Store.init_schema()` 后新增 3 张收益表和 1 个索引；不删除、清空或重建旧用户/会话表。
4. 管理员访问软件管理后台 → 创作收益：读取默认 35%，修改、保存、重新读取。普通用户直接请求同接口应返回 403。
5. 用合成作者和玩家测试：消费 100 积分，作者奖励余额增加 35，收益页该卡增加 35；100 次各消耗 1 积分同样得到 35。重复同一结算 ID 只扣一次、只分一次。积分不足不得产生收益。非作者不能读取他人收益。
6. 验证后由维护人员安排生产部署；本包未执行该动作。APK 保留既有服务器地址。

## 接口

- `GET /console/api/web/earnings`：必须登录，按服务端当前身份返回 `{unit:'积分',creator_points,cards:[{app_id,name,points}],invite_points:null}`（外层沿用 ok_response）。
- `GET /admin/api/creator-revenue`：必须管理员，返回 `{rate_bps:3500}`。
- `PUT /admin/api/creator-revenue`：必须管理员，提交 `{rate_bps:4050}` 表示 40.50%；无效类型/越界值返回 400。修改者与前后值写入 user_events。

## 回退

停服务后恢复改动前的服务端代码即可停止未来分成；不要删除新表或自动扣回已经发放的积分。若要回退数据库，须人工核对备份后的真实用户消费，不能直接覆盖运行中的数据库。
